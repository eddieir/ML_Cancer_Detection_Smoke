# constraints-ci.txt — pins the direct scientific/runtime/test dependencies
# that can materially affect test-suite behavior for the Linux/Python 3.11
# CI environment this project is validated against.
#
# This is a pip constraints file (see
# https://pip.pypa.io/en/stable/user_guide/#constraints-files): it does not
# add or remove packages, it only narrows the version `pip install -r
# requirements.txt -c constraints-ci.txt` is allowed to resolve to, so
# `requirements.txt` can keep documenting the broader supported ranges.
#
# Scope and honesty notes:
#   * These exact versions are evidence-based — captured from the local
#     development environment (Python 3.11.13) whose resolution of the SAME
#     unconstrained requirements.txt independently matched every version
#     reported by the last completed CI job (Python 3.11.15): torch 2.13.0,
#     scanpy 1.11.5, anndata 0.12.19, celltypist 1.7.1, scikit-learn 1.9.0,
#     numpy 2.4.6, pandas 2.3.3, scipy 1.17.1. That match is not proof pip's
#     resolver will reproduce it forever on a clean network install — it is
#     the strongest reproducibility evidence available without re-running
#     CI, and pinning these now stops future drift from this known-good
#     combination.
#   * This file targets Linux (the CI runner's `ubuntu-latest`) and
#     Python 3.11 specifically. It is NOT a full cross-platform lock file —
#     no claim is made about macOS/Windows or other Python versions.
#   * `jupyter` is intentionally NOT pinned here: it is not imported by any
#     module under src/ or tests/, so its resolved version cannot affect
#     test-suite behavior; it remains governed only by the loose bound in
#     requirements.txt.
#   * `pybiomart` and `harmonypy` are pinned to the versions actually
#     resolved locally even though they were not called out in the CI job's
#     printed version summary, because pip freeze in the environment whose
#     other packages matched CI confirmed these exact versions.
